# RAG по статьям Хабра

Учебная лабораторная: LangChain, рекурсивные чанки, локальный эмбеддер VK,
гибридный поиск BM25 + FAISS и ответы GPT-6 Luna (medium effort) через OpenAI API.
Интерфейс — Streamlit. Отдельный `main.ipynb` показывает очистку одной статьи.

## Файлы

- `chunking.py` — потоковое чтение JSON, очистка HTML, удаление дублей, чанкинг.
- `retrieval.py` — эмбеддинги, FAISS, BM25 и объединение результатов через RRF.
- `llm.py` — запрос GPT-6 Luna через LangChain, ответ со ссылками `[1]`, `[2]`.
- `app.py` — интерфейс: вопрос, ответ, найденные фрагменты и ссылки.
- `main.ipynb` — пошаговый разбор CSV/JSON, HTML, очистки и чанкинга первой статьи.
- `evaluation.json`, `evaluate.py` — фиксированные вопросы и оценка поиска/ответов.
- `../data/raw/habr` — исходная выгрузка из материалов; программа её не меняет.

## Docker

Из папки `lab_2_langchain` при работающем Docker Desktop:

```bash
docker compose up --build -d
```

Открыть http://localhost:8501 и нажать «Собрать базу знаний».
Первый запуск скачивает `deepvk/USER2-small` (~140 МБ весов); модель сохраняется
в Docker volume `model-cache`. Данные и полный FAISS подключены только для чтения
и не входят в образ. Сохранённый FAISS из `../data/indexes/habr` используется после
сверки количества, порядка и точного текста всех чанков, а также трёх контрольных
векторов текущего эмбеддера. BM25 собирается в памяти.
Если подходящего FAISS нет, эмбеддинги строятся заново; это лучше сделать на GPU
через `python -m scripts.build_indexes` из корня курса до запуска контейнера.
Параметры задаются в коде: `ARTICLE_LIMIT = None` в `app.py` — все статьи файла;
`TOP_K = 10` — количество найденных чанков для LLM.
После изменения данных или параметров перезапустить приложение;
для Docker повторить `docker compose up --build -d`.

Ключ OpenAI можно ввести в поле интерфейса. Другой вариант — задать переменную
`OPENAI_API_KEY` в корневом `../.env`, который читает Compose и который исключён
из Git. Без ключа приложение показывает только источники.
В API передаются вопрос и найденные фрагменты, а не вся выгрузка.

```bash
docker compose logs -f rag
docker compose down
```

## Данные и алгоритм

Для изучения очистки откройте `main.ipynb` в VS Code/Jupyter, выберите окружение
`main` и выполните ячейки сверху вниз.
Ноутбук читает только первую статью, не скачивает эмбеддер и не вызывает API.

Текущий Light-набор — 10 000 строк CSV.bz2; после очистки у 9999 есть текст.
Читаем по одной строке, не распаковывая весь файл в память. Используем
`post_title`, `post_html`, `post_id`, дату и хабы. Загрузчик также поддерживает
старый JSON `{хаб: [статьи]}` через `ijson`: там поля называются `titleHtml`,
`textHtml`, а при отсутствии текста берётся анонс `leadData.textHtml`.
Удаляем HTML-теги, скрипты, стили,
лишние пробелы и пустые тексты. Сохраняем абзацы и текст кода; изображения,
оформление таблиц и исходные отступы кода в RAG не переносятся. Служебные поля
пользователей, статистики и интерфейса Хабра не индексируются.
Дубли отсекаются по ID и хешу очищенного текста с заголовком.

Берём все 9999 уникальных непустых статей доступного Light-файла. Значение
`limit=None` теперь используется по умолчанию и в `load_documents`, и в приложении.
Это весь текущий файл, а не весь сайт Хабр. Одна строка без извлекаемого текста
пропускается. Параметры задаются в коде, в интерфейсе ограничения числа статей нет.

`RecursiveCharacterTextSplitter`: 1000 символов, перекрытие 150. VK-эмбеддер
использует префиксы `search_document` и `search_query`, нормализованные векторы
и GPU при наличии CUDA (иначе CPU). BM25 приводит слова к нижнему регистру и заменяет «ё» на «е», без
лемматизации. Каждый поиск отдаёт до 20 кандидатов. RRF складывает
`2 / (60 + позиция FAISS) + 1 / (60 + позиция BM25)`; отсутствующий в выдаче
поиска чанк не получает его слагаемое. Веса 2:1 выбраны на validation-вопросах;
отложенные вопросы не использовались для настройки. В LLM уходят лучшие 10 чанков.
BM25-кандидаты без общих слов с вопросом отбрасываются. Оценка RRF не является
вероятностью релевантности. Несколько фрагментов могут относиться к одной статье.

GPT-6 Luna отвечает отдельно на каждый вопрос, без истории диалога. Responses API,
reasoning effort `medium`, до 6000 выходных токенов вместе с reasoning,
timeout 120 секунд, два повтора. Temperature и top_p не передаются.
Отсутствие подходящих сведений в выбранных статьях должно отражаться в ответе;
ссылки и утверждения модели всё равно стоит сверять с показанными фрагментами.

## Проверка

Текущая оценка всего корпуса: [`QUALITY.md`](QUALITY.md). Для повторения на `home`
из корня курса:

```bash
mamba run -n main python lab_2_langchain/evaluate.py --split validation
mamba run -n main python lab_2_langchain/evaluate.py --split holdout
mamba run -n main python lab_2_langchain/evaluate.py --split challenge
```

Результаты, ответы и точный контекст сохраняются в `data/lab2_quality/`.
`--no-generation` отключает платные вызовы API и проверяет только поиск.
После проверки контейнер первой лабы остановлен. Для запуска позже выполните
`docker compose up -d` из этой папки на `home`. Данные, индекс и образ сохранены.

Тестовые файлы не добавляются. Проверка вручную: сборка Docker, health endpoint,
индексация части реального корпуса, гибридный поиск и просмотр источников
в интерфейсе. Ответ API требует действующего ключа OpenAI с доступом к модели.

Исторический замер до снятия ограничения 500: чтение, очистка и чанкинг 500 статей —
2.77 с, получено 6221 чанков. Полный сценарий с FAISS/BM25, поиском и реальным
ответом GPT-6 Luna — 24.88 с при уже скачанной модели. Ноутбук выполнен с чистого
ядра: 10 ячеек кода, 0 ошибок. Подробности — в корневом `VERIFICATION.md`.

План выполнения: разобрать статью в ноутбуке → очистить корпус → получить чанки →
построить BM25 и FAISS → объединить выдачу → проверить ответ и источники.
