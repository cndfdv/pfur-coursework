# Качество RAG на всём доступном Хабре

Проверка 09.11.2026 на `ssh home`, mamba `main`. Модель ответов — GPT-6 Luna,
reasoning effort `medium`. Дообучение и внешние поисковые источники не использовались.

## Что обработано

Весь текущий Light-файл: 10 000 строк, 9999 непустых уникальных статей, 0 дублей,
1 запись без извлекаемого текста. Получено **142 611 чанков**. Ограничение 500
снято: `ARTICLE_LIMIT = None`, `load_documents(limit=None)` по умолчанию.
Это весь доступный файл, не весь сайт Хабр и не прежняя полная выгрузка.

Чанки — 1000 символов, перекрытие 150. VK `deepvk/USER2-small`, 384 измерения,
нормализованные векторы, FAISS IndexFlatIP. BM25: нижний регистр, `ё → е`,
без лемматизации. Каждый метод даёт 20 кандидатов; в LLM поступают 10 чанков.

## Как проверяли

В `evaluation.json` заранее записаны вопросы, ID ожидаемых статей и эталонные
факты. Для 20 обычных вопросов взято по статье из равномерно распределённых
позиций файла: от первой до последней. 12 вопросов — validation, 8 — holdout;
они перемежаются по всему файлу. Ещё 4 — дополнительные трудные сценарии.

Документы holdout включены в индекс: RAG должен находить их, это не утечка.
Отложены именно вопросы, не документы. На holdout не подбирались веса,
пороги, текст вопросов или промпт. Генерация каждого holdout-ответа выполнена один раз.

Сравниваются три поиска на одинаковых чанках и с бюджетом 10 чанков:
BM25, FAISS и гибрид RRF. Проверка ответов отдельно учитывает правильность,
полноту и поддержку утверждений цитируемыми фрагментами.

Содержательную проверку провели ассистент и отдельный ML-reviewer по эталонам
и сохранённому контексту. Это не независимая разметка человеком и не оценка
истинности публикаций относительно внешнего мира.

## Качество поиска

**Hit@k**: известная нужная статья встречается среди первых k **чанков**.
**MRR@10**: среднее `1 / позиция первого чанка нужной статьи`, либо 0 при промахе.
Это не recall всех релевантных статей: альтернативные правильные источники
полностью не размечались. Повторы чанков одной статьи учитываются как позиции.

| Набор | Метод | Hit@1 | Hit@5 | Hit@10 | MRR@10 |
|---|---|---:|---:|---:|---:|
| Validation, 12 | BM25 | 66.7% | 83.3% | 91.7% | 0.764 |
| Validation, 12 | FAISS | 91.7% | 91.7% | 100% | 0.927 |
| Validation, 12 | Гибрид 2:1 | 91.7% | 91.7% | 100% | 0.926 |
| Holdout, 8 | BM25 | 100% | 100% | 100% | 1.000 |
| Holdout, 8 | FAISS | 62.5% | 100% | 100% | 0.771 |
| Holdout, 8 | Гибрид 2:1 | 87.5% | 100% | 100% | 0.938 |

Гибрид нашёл известный источник в top-10 во всех 20 обычных вопросах. Однако
его превосходство над отдельными методами не доказано: на holdout BM25 занял
первые места лучше, а FAISS на validation имеет чуть больший MRR.
Вопросы часто содержат названия продуктов, поэтому сильный BM25 здесь ожидаем.

## Что исправлено по validation

При равных весах RRF гибрид находил источник в 11 из 12 validation-вопросов.
В q03 спрашивался швейцарский город исследовательского центра Google.
FAISS нашёл нужную статью на позиции 8; BM25 её не нашёл в top-10. При объединении
двух списков с равными весами полезный чанк выпал из контекста. Модель корректно
сообщила, что город не указан, но ответ на вопрос не дала.

Выбраны веса **FAISS:BM25 = 2:1**:

```text
score = 2 / (60 + rank_FAISS) + 1 / (60 + rank_BM25)
```

Отсутствие чанка в списке означает отсутствие соответствующего слагаемого.
После изменения нужный фрагмент q03 оказался на позиции 9. Ответ «Цюрих [9]»
прямо подтверждается этим фрагментом. Это настройка по validation, а не отдельное
независимое доказательство улучшения. Веса после запуска holdout не менялись.

## Ответы и сложные случаи

| Проверка | Результат |
|---|---|
| Обычные validation-вопросы | 12/12 правильных и подтверждённых ответов |
| Обычные holdout-вопросы | 8/8 правильных и подтверждённых ответов |
| Номера ссылок обычных ответов | 20/20 в допустимом диапазоне; содержимое также проверено |
| q21: сравнить ОЗУ Chat with RTX и Windows Dev Kit | **Неполный ответ**: 16 ГБ для RTX, сведений про Dev Kit в контексте нет |
| q22: память вымышленной «Снежинка ZX-9099» | Корректное сообщение об отсутствии сведений |
| q23: масса вымышленного робота «Тихон RX-7319» | Корректное сообщение об отсутствии сведений |
| q24: год рождения бабушки главы SoundCloud | Корректное сообщение об отсутствии сведений |

Для q21 в top-10 попала только одна из двух нужных статей. Полнота поиска
источников — **1/2**, фактов — также 1/2. Модель не придумала недостающие 32 ГБ,
но полностью сравнить устройства не смогла. Такой запрос лучше задать двумя
простыми предложениями: их разбиение поддерживает лабораторная 4.

В q23 модель поставила избыточную ссылку `[1]–[10]`. Простая регулярка в отчёте
выделяет только номера 1 и 10, не разворачивая диапазон. Сам отказ проверен по
всем десяти фрагментам. Автоматическое поле `citations_valid` проверяет номера,
а не фактическую поддержку текста — последняя проверялась отдельно.

## Совместимость эмбеддингов и сохранённого индекса

Полный FAISS переиспользуется после посимвольной сверки текста и порядка всех
142 611 чанков. Также проверяются число векторов, метрика, размерность и три
эмбеддинга: первый, средний и последний. Это выборочная проверка совместимости
модели, а не повторное вычисление всего индекса.

Дополнительная диагностика обнаружила, что стандартная обёртка
`HuggingFaceEmbeddings` заменяет переносы строк пробелами, а общий индекс строился
на исходных строках. Для согласованности добавлен небольшой стандартный адаптер
LangChain `Embeddings`, явно вызывающий SentenceTransformer без этой замены.
Префиксы `search_document` и `search_query` и нормализация сохранены.

Три контрольных вектора нового адаптера совпали с индексом: максимальное
абсолютное различие `9.69e-8`, cosine около 1. Ревизия USER2 при проверке:
`23f65b34cf7632032061f5cc66c14714e6d4cee4`. Хеши файла данных, индекса,
чанков и исходников, а также версии пакетов записаны в `provenance.json`.

Все 24 вопроса однострочные: техническая замена адаптера для них не должна
менять вход эмбеддера. Проверка `embedding_regression.json` подтвердила:
для всех 24 вопросов максимальное изменение векторов запросов — **0.0**,
полные top-10 BM25/FAISS/гибрида остались **идентичными** сохранённым прогонам.
Поэтому повторная генерация и подгонка на holdout не выполнялись.

## Полный интерфейс и время запуска

В Docker проверено нажатие «Собрать базу знаний»: 9999 статей, 142611 чанков,
10000 просмотренных строк. Полное повторное вычисление эмбеддингов было
запрещено проверкой: выполнялись только 3 контрольных эмбеддинга. Сборка
состояния интерфейса заняла 94.45 с на CPU при готовом FAISS; вместе с реальным
ответом про Tesla — 98.74 с. Это один замер, включая очистку HTML и BM25,
не обещание постоянного времени запуска. Дальнейшие вопросы используют индекс
в памяти. JSON измерения — `ui_full_verification.json`.

После проверки контейнеры лабораторных на `home` остановлены. Исходные данные,
индексы, образ и кэш модели сохранены для следующего запуска.

## Как повторить

На `home`, из корня `third_semestr`, после загрузки исходных данных:

```bash
mamba run -n main python lab_2_langchain/evaluate.py --split validation
mamba run -n main python lab_2_langchain/evaluate.py --split holdout
mamba run -n main python lab_2_langchain/evaluate.py --split challenge
```

JSON с вопросами, ответами, всеми десятью фрагментами и метриками находится в
`data/lab2_quality/` локально и на сервере. Исходный результат с равными весами
сохранён как `validation_baseline.json`. `--no-generation` проверяет только поиск.

Выборка мала, вопросы составлены вручную по статьям и часто содержат точные
названия. Здесь нет проверки всех возможных тем, диалогов, скрытых инъекций
или статистического доказательства качества на произвольных вопросах.
