# Теория для защиты лабораторных 1-7

## Лаба 1: культура кода, типизация, анализ текста

### PEP 8

PEP 8 — это стандарт оформления Python-кода. Он нужен, чтобы код был читаемым и единообразным: понятные имена, отступы 4 пробела, ограничение длины строк, пустые строки между функциями.

Короткий ответ на защите: PEP 8 не меняет логику программы, но делает код проще для чтения, ревью и поддержки.

### Type hints

Аннотации типов показывают, какие типы данных функция принимает и возвращает:

```python
def analyze_text(text: str) -> dict[str, int | float]:
    ...
```

Python сам по себе не запрещает передать неправильный тип, но type hints помогают IDE, `mypy`, ревьюеру и самому разработчику быстрее находить ошибки.

### Docstring

Docstring — строка документации внутри функции, класса или модуля. Она объясняет назначение кода, аргументы и результат.

### Обработка текста

В лабораторной текст проходит несколько этапов:

1. Приведение к нижнему регистру через `lower()`.
2. Удаление пунктуации через `str.translate`.
3. Разбиение строки на слова через `split()`.
4. Подсчёт статистики.

`set` используется для уникальных слов, потому что множество хранит только неповторяющиеся элементы.

### Что могут спросить

Вопрос: зачем нужен `set`?

Ответ: чтобы убрать повторы и посчитать количество уникальных слов.

Вопрос: зачем нужна типизация, если Python динамический?

Ответ: она не обязательна во время выполнения, но помогает инструментам и разработчикам заранее видеть ошибки типов.

Вопрос: что такое линтер?

Ответ: инструмент, который проверяет стиль и потенциальные проблемы в коде, например `flake8`.

## Лаба 2: ООП и векторы

### Класс и объект

Класс — это шаблон или описание типа данных. Объект — конкретный экземпляр класса.

В лабораторной `Vector` — класс, а `Vector(1, 2, 3)` — объект.

### Атрибуты и методы

Атрибуты — данные объекта, например координаты вектора. Методы — функции внутри класса, которые работают с объектом.

### `self`

`self` — ссылка на текущий объект. Через него метод получает доступ к координатам конкретного вектора.

### `__init__`

`__init__` вызывается при создании объекта и задаёт начальное состояние:

```python
v = Vector(1, 2, 3)
```

В этот момент координаты сохраняются в объект.

### `*args`

`*args` позволяет принять произвольное количество позиционных аргументов. Это удобно для N-мерного вектора, потому что координат может быть 2, 3, 10 и так далее.

### Магические методы

Магические методы начинаются и заканчиваются двойным подчёркиванием. Python вызывает их автоматически.

- `__repr__` отвечает за строковое представление объекта.
- `__add__` вызывается при `a + b`.
- `__mul__` вызывается при `a * b`.

### Скалярное произведение и умножение на число

Умножение вектора на число возвращает новый вектор:

```text
(1, 2, 3) * 2 = (2, 4, 6)
```

Умножение вектора на вектор возвращает число:

```text
(1, 2, 3) * (4, 5, 6) = 1*4 + 2*5 + 3*6 = 32
```

### `@property`

`@property` позволяет обращаться к методу как к атрибуту:

```python
v.norm
```

А не так:

```python
v.norm()
```

Это удобно, потому что длина вектора выглядит как характеристика объекта.

### Что могут спросить

Вопрос: почему нельзя складывать векторы разной размерности?

Ответ: сложение векторов выполняется покомпонентно, поэтому каждой координате первого вектора должна соответствовать координата второго.

Вопрос: зачем `isinstance` в `__mul__`?

Ответ: чтобы понять, умножаем мы на число или на другой вектор, и выбрать правильную логику.

## Лаба 3: исключения, файлы, архитектура

### Исключения

Исключение — это объект ошибки, который можно выбросить через `raise` и обработать через `try/except`.

В проекте есть кастомные исключения:

- `BaseAppError` — базовое исключение приложения.
- `DataFormatError` — проблема с форматом файла.
- `ValidationError` — проблема с данными конкретной записи.
- `CurrencyMismatchError` — заготовка для ошибки валют.

### Зачем кастомные исключения

Они позволяют отделить ошибки приложения от системных ошибок Python. Например, можно отдельно обработать битый CSV и отдельно ошибку записи на диск.

### Fail fast

Fail fast — принцип “падаем сразу”, если продолжать опасно. Например, если входной директории нет, программа не может корректно работать.

### Graceful degradation

Graceful degradation — программа продолжает работать частично. Например, если одна строка битая, она логируется и отбрасывается, а остальные строки обрабатываются.

### Слоистая архитектура

Проект разделён на слои:

- `app/io` — чтение CSV/JSON.
- `app/services` — валидация и агрегация.
- `app/core` — модели и исключения.
- `main.py` — точка входа и сборка пайплайна.

Такой код проще расширять: чтобы добавить новый формат файла, не нужно переписывать всю программу.

### Registry pattern

Registry pattern — словарь, который связывает расширение файла с reader-функцией:

```python
READERS = {
    ".csv": read_csv,
    ".json": read_json,
}
```

Это убирает длинные `if/elif` и упрощает добавление новых форматов.

### Логирование

`logging` лучше `print`, потому что умеет писать уровни сообщений, время, файл логов и пригоден для production-кода.

Основные уровни:

- `info` — обычная информация;
- `warning` — проблема, но программа работает;
- `error` — ошибка операции;
- `critical` — критическая проблема.

### Атомарная запись

Результат сначала пишется во временный файл, потом заменяет старый через `os.replace`.

Зачем: если программа упадёт во время записи, основной `result.json` не останется наполовину записанным.

### Что могут спросить

Вопрос: почему битая строка не валит программу?

Ответ: потому что ошибка в одной записи не должна мешать обработке остальных данных. Она логируется и попадает в отчёт.

Вопрос: почему чтение отделено от валидации?

Ответ: чтение отвечает только за формат файла, а валидация — за бизнес-правила. Это разные ответственности.

## Лаба 4: тестирование

### Зачем нужны тесты

Тесты нужны, чтобы проверять поведение программы автоматически и не ломать старую логику при изменениях.

### Unit-тесты

Unit-тест проверяет маленькую часть кода изолированно. Например, `validate` на разных значениях `amount`.

### Integration-тесты

Integration-тест проверяет совместную работу нескольких частей: чтение файла, валидацию, агрегацию, сохранение результата.

### AAA

AAA — структура хорошего теста:

1. Arrange — подготовка данных.
2. Act — действие, вызов функции.
3. Assert — проверка результата.

### Fixtures

Фикстуры в pytest — функции подготовки данных для тестов. Например, создать временный CSV или вернуть валидную запись.

### `tmp_path`

`tmp_path` создаёт временную директорию для теста. После теста она автоматически удаляется. Это нужно, чтобы тесты не мусорили в проекте.

### Parametrize

`pytest.mark.parametrize` позволяет одним тестом проверить много входных значений.

### Mock и patch

Mock — подмена реального объекта тестовой заглушкой. `patch` временно заменяет функцию или метод.

В лабораторной `patch` используется, чтобы имитировать ошибку записи на диск.

### Coverage

Coverage показывает, какая доля строк кода была выполнена во время тестов.

Важно: высокий coverage не гарантирует отсутствие багов. Он говорит только, что код был пройден тестами.

### Что могут спросить

Вопрос: чем unit-тест отличается от integration-теста?

Ответ: unit проверяет одну функцию изолированно, integration проверяет связку нескольких модулей.

Вопрос: зачем mock?

Ответ: чтобы проверить редкую или опасную ситуацию без реального воздействия на систему, например ошибку диска.

## Лаба 5: ленивые вычисления и Big Data

### Проблема больших файлов

Если сделать `readlines()` или собрать все строки в список, большой файл загрузится в память целиком. Для файла на гигабайты это может привести к `MemoryError`.

### Итератор

Итератор — объект, который отдаёт элементы по одному. У него есть методы `__iter__` и `__next__`.

### Генератор

Генератор — функция с `yield`. Она отдаёт значение, ставит выполнение на паузу, а потом продолжает с того же места.

Пример:

```python
def numbers():
    yield 1
    yield 2
```

### Lazy evaluation

Ленивые вычисления означают, что данные обрабатываются только тогда, когда они реально нужны, и по одному элементу, а не заранее все сразу.

### Pipeline

Pipeline — цепочка обработки:

```text
чтение -> парсинг -> валидация -> агрегация
```

Каждый этап отдаёт данные следующему постепенно.

### Память O(1) или O(K)

В лабораторной не хранятся все транзакции. Хранится только словарь сумм по категориям.

Если категорий мало, память почти не растёт от размера файла. Формально это O(K), где K — количество категорий.

### `tracemalloc`

`tracemalloc` измеряет использование памяти Python-кодом. В лабораторной он нужен, чтобы показать пиковое потребление памяти при обработке данных.

### Что могут спросить

Вопрос: почему генератор лучше списка для большого файла?

Ответ: генератор отдаёт элементы по одному и не хранит весь файл в памяти.

Вопрос: что делает `yield`?

Ответ: возвращает одно значение из генератора и сохраняет состояние функции до следующего запроса.

Вопрос: почему агрегация не требует хранить все транзакции?

Ответ: для каждой новой транзакции достаточно обновить сумму её категории.

## Лаба 6: асинхронность и I/O

### Синхронный код

Синхронный код выполняет операции последовательно. Если один сетевой запрос ждёт ответ, вся программа ждёт вместе с ним.

### I/O-bound задача

I/O-bound — задача, где основное время тратится не на вычисления CPU, а на ожидание ввода-вывода: сеть, диск, база данных.

Сетевые запросы — типичный пример I/O-bound.

### Асинхронность

Асинхронность позволяет программе переключаться между задачами во время ожидания I/O.

Это не обязательно параллелизм. Часто всё работает в одном потоке, но event loop переключает корутины.

### Event loop

Event loop — цикл событий, который управляет выполнением корутин: запускает их, приостанавливает на `await` и продолжает, когда операция готова.

### Coroutine

Корутина — функция, объявленная через `async def`. Она может приостанавливаться через `await`.

### `await`

`await` говорит event loop: эта операция ждёт, можно пока выполнять другие задачи.

### `asyncio.gather`

`gather` запускает набор корутин конкурентно и ждёт, пока они все завершатся.

### `aiohttp.ClientSession`

`ClientSession` — асинхронная HTTP-сессия. Её лучше создавать один раз на много запросов, потому что она переиспользует соединения.

### Semaphore

`asyncio.Semaphore` ограничивает количество одновременных задач. Это защищает от перегрузки сервера и лимита открытых соединений.

### Timeout

Timeout нужен, чтобы запрос не висел бесконечно. Если сервер не отвечает, корутина ловит ошибку и возвращает `{}`.

### Почему нельзя `requests` внутри async

`requests.get()` блокирует поток. Если вызвать его внутри `async def`, он заблокирует весь event loop, и асинхронность потеряет смысл.

### Что могут спросить

Вопрос: асинхронность и многопоточность — одно и то же?

Ответ: нет. Асинхронность обычно конкурентно переключает задачи в одном потоке, а многопоточность использует несколько потоков ОС.

Вопрос: зачем семафор?

Ответ: чтобы ограничить число одновременных запросов и не перегрузить сервер или свою систему.

## Лаба 7: Git

### Commit

Commit — снимок состояния проекта в истории Git.

### Branch

Branch — указатель на коммит. Ветки позволяют вести разработку разных задач независимо.

### HEAD

`HEAD` указывает на текущий коммит или текущую ветку.

### Checkout / switch

`checkout` или `switch` переключает рабочую директорию на другую ветку или коммит.

### Merge

`merge` объединяет изменения из одной ветки в другую. История ветвления сохраняется.

### Rebase

`rebase` переносит коммиты текущей ветки поверх другого коммита. История становится линейнее, но коммиты переписываются.

Коротко: `merge` сохраняет историю ветвления, `rebase` переписывает базу коммитов.

### Cherry-pick

`cherry-pick` переносит один выбранный коммит в текущую ветку.

### Remote

Remote — удалённый репозиторий, например GitHub. Обычно называется `origin`.

### Fetch, pull, push

- `fetch` скачивает изменения с remote, но не применяет их к текущей ветке.
- `pull` скачивает и сразу интегрирует изменения.
- `push` отправляет локальные коммиты на remote.

### `origin/main`

`origin/main` — локальный указатель на состояние ветки `main` в удалённом репозитории `origin` после последнего `fetch` или `pull`.

### Что могут спросить

Вопрос: чем `fetch` отличается от `pull`?

Ответ: `fetch` только скачивает данные, `pull` скачивает и сразу сливает или ребейзит в текущую ветку.

Вопрос: почему опасно ребейзить публичную ветку?

Ответ: rebase переписывает историю коммитов. Если эту историю уже используют другие люди, у них могут появиться конфликты и расхождения.
