# Шпаргалка по лабораторным: суть, запуск, защита

## Лаба 1: анализ текста

Где лежит:

```bash
second_semestr/lab_1/
```

Суть: функция `analyze_text` принимает строку, приводит текст к нижнему регистру, убирает пунктуацию, разбивает на слова и считает:

- общее количество слов;
- количество уникальных слов;
- среднюю длину слова.

Как запустить:

```bash
cd second_semestr/lab_1
python -c "from text_analyzer import analyze_text; print(analyze_text('Hello, hello world!'))"
```

Ещё можно открыть ноутбук:

```bash
jupyter notebook main.ipynb
```

Что защищать:

- как работает `lower()`;
- зачем нужен `str.translate`;
- чем `list` отличается от `set`;
- почему средняя длина считается как сумма длин слов, делённая на количество слов;
- что будет, если передать пустую строку: сейчас будет деление на ноль, это можно назвать ограничением текущей реализации.

## Лаба 2: ООП и векторы

Где лежит:

```bash
second_semestr/lab_2/
```

Суть: класс `Vector` реализует математический вектор произвольной размерности. Есть сложение векторов, умножение на число, скалярное произведение и вычисление длины вектора.

Как запустить:


Ещё можно открыть ноутбук:

```bash
jupyter notebook main.ipynb
```

Что защищать:

- что такое класс и объект;
- зачем нужен `__init__`;
- зачем нужен `__repr__`;
- как работают магические методы `__add__` и `__mul__`;
- почему нельзя складывать векторы разной размерности;
- чем умножение на число отличается от скалярного произведения;
- что такое евклидова норма: корень из суммы квадратов координат.

## Лаба 3: отказоустойчивая обработка файлов

Где лежит:

```bash
second_semestr/lab_3/
```

Суть: консольная программа читает финансовые отчёты из CSV и JSON, валидирует транзакции, пропускает битые записи, логирует ошибки и сохраняет итоговые суммы по категориям в `result.json`.

Как запустить:

```bash
cd second_semestr/lab_3
python main.py data result.json
```

После запуска смотри:

- `result.json` — итоговая агрегация;
- `app.log` — ошибки по битым файлам и строкам.

Что защищать:

- слоистую архитектуру: `io`, `services`, `core`;
- зачем нужны кастомные исключения;
- разницу между `ValidationError` и `DataFormatError`;
- почему одна битая строка не должна валить всю программу;
- что такое graceful degradation;
- зачем нужен `pathlib.Path`;
- почему результат пишется через временный файл и `os.replace`.

## Лаба 4: тестирование

Где лежит:

```bash
second_semestr/lab_4/
```

Суть: покрытие проекта из лабы 3 тестами. Есть unit-тесты для моделей и валидатора, integration-тесты для полного пайплайна, фикстуры, параметризация и mock для ошибки записи.

Как запустить:

```bash
cd second_semestr/lab_4
pytest -q
```

Покрытие уже включено в `pytest.ini`, поэтому после запуска появится отчёт coverage.

Что защищать:

- что такое unit-тест;
- что такое integration-тест;
- паттерн AAA: Arrange, Act, Assert;
- зачем нужен `tmp_path`;
- зачем нужен `pytest.mark.parametrize`;
- зачем нужен `unittest.mock.patch`;
- почему тесты должны проверять не только успешный сценарий, но и ошибки;
- что означает coverage и почему 100% покрытия не гарантирует отсутствие багов.
